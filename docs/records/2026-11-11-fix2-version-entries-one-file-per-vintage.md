# Fix request 2, merge churn and RH-D1: one file per extraction vintage, current is the head, one pin file per watched module (strict). No page moves

**WHAT.**
- **The churn.** Every PR that changed extraction output appended a row at the end of
  `EXTRACTION_VERSIONS` (`vinci/dossier/extraction_version.py`) and of its hand-kept twin in
  `frontend/views/shared/dossier.js`, and re-pinned a shared block in
  `tests/test_extraction_version_drift.py` (`WATCHED`, `PINNED_TABLE`, `PINNED_AT`). Every other
  open PR then went DIRTY on those lines, and each re-sync cost a 30–80 minute re-gate.
- **The table.** Every row merged under the one-tuple table (79 at main `173b4818`) is frozen as
  `LEGACY_VERSIONS`, unchanged byte for byte. Each new
  vintage is one file, `vinci/dossier/extraction_versions/<YYYY-MM-DD>.<slug>.json`, holding `id`,
  `follows` and `names`. `python -m vinci.dossier.extraction_version new <slug> --names "…"`
  writes it. A counter slug (`.1`) is refused: two PRs pick the same next number.
- **Order and current.** Order is ancestry: a vintage includes every vintage it follows,
  transitively, and each frozen row follows the row above it. Current is the set of heads, the
  vintages nothing follows. With one head, the stamp is its id, exactly as before. With two or
  more heads (PRs cut from the same main and merged in either order), the stamp is their ids
  joined by `+` in id order. That stamp is declared, and its detail names each part. The next
  vintage written there follows every head, and the join closes. Readers that compared row
  positions (`tests/test_footnote_every_figure.py`) now ask `includes(stamp, ref)`. Membership
  readers ask `declares(stamp)`.
- **The web.** `dossier.js` holds no table. `frontend/build.py` writes
  `frontend/snapshots/extraction_versions.json` (versions and parents) on every deploy. That
  folder is git-ignored and regenerated by the Pages build step, so nothing committed is generated
  per vintage. `render()` fetches the table and sets it (`useExtractionVersions`) before the page
  is drawn; the four render functions keep their signatures. A table that does not load is said on
  the page, never read as "not a version this code declares".
- **The pins (RH-D1).** Each watched module has one file, `tests/extraction_pins/<module>.pin` =
  `<code hash> <why>`, where `why` is the vintage that declared the change or `refactor`. The rule
  is strict: every watched module's hash equals its pin. The old rule accepted any move once the
  table held a row the pins had not seen, and said so only through `warnings.warn`, which every
  gate's `-p no:warnings` dropped. That window no longer exists. `--repin --entry <id>` rewrites
  only the pins whose hash moved.

**WHY.**
- *Why not sort by date.* The frozen table was replayed in its real merge order. For each append,
  the check was whether a "current" chosen by sorting ids would have moved. It would not have on
  **47 of 78 appends** (e.g. `2026-11-09.driver-facts` merged after `2026-11-10.point-guide`). The
  stamp would have stood still while the code moved, which is the defect A-D14 recorded. It is
  live on main as this is written: #961 and #970 merged `2026-11-10.*` rows after
  `2026-11-11.guides-as-stated`, so a sorted current would still name the latter. Ancestry needs
  no knowledge of merge order.
- *Why the strict pins can now hold.* The old global digest could never match a merge of two
  re-pinned branches. That is why the rule had to be loose. Per-module files carry no shared
  line. Two PRs that move different modules merge clean, and each pin matches the merged tree. Two
  PRs that move the same module conflict on that pin file. That conflict is wanted: the merged
  module's hash is new and must be re-pinned.

**HOW VERIFIED.**
- **(a) Merge probe.** Two throwaway branches per side. Each changes one watched module
  (`vinci/finra.py`, `vinci/verbatim.py`) and declares it by that side's documented procedure.
  - On main `2b9b766c`, `git merge-tree` exits 1 with conflicts in `extraction_version.py`,
    `dossier.js` and the drift test.
  - On this branch it exits 0. Merging in either order gives one tree. On that tree the stamp is
    `2026-11-11.probe-x+2026-11-11.probe-y`, and the drift, table and parity tests pass under the
    gate's flags.
  - The same-module case (two branches moving `vinci/finra.py`) conflicts on
    `tests/extraction_pins/vinci/finra.py.pin`, as it must.
- **(b) Pages.** Every committed `data/dossiers/*/dossier.json` (27) was rendered at main and at
  head: the markdown, Python's `stamp_label`/`stamp_detail`/`refreshed_to`/`refresh_line`, and the
  web's header, Extraction row and refresh lines through `renderDossier` in node. All are
  identical on 27 of 27. `frontend/build.py` at main and head gives identical `frontend/dossiers/`
  (55 files). The snapshot mirror differs only by the manifest's timestamp and the new git-ignored
  index.
- **(c) Python and JS agree.** On 27 of 27 pages the web's Extraction row equals Python's
  `stamp_detail`, and its refresh lines equal `refresh_line`. On a synthetic table holding two
  heads, both twins agree on every join shape, good and bad
  (`tests/test_extraction_version_entries.py`). In a real browser (a local server over the built
  mirror), FUBO's row reads its stamp and words from the fetched table, with no console error.
- **RH-D1, fail first.** The stale state is a vintage added, then `vinci/edgar/net_debt.py` moved,
  with the pins untouched. It was run with `pytest -m "not network" -p no:warnings --tb=short
  -rs`.
  - At main, the invariant and the stale-warning test both PASS. The file's one red is
    `test_the_failure_tells_a_merger_each_step` (`DID NOT RAISE`), an accident of its own
    monkeypatch, which names no module.
  - At head, `test_a_watched_module_never_moves_without_its_pin` FAILS and names
    `vinci/edgar/net_debt.py`.
  - `test_a_stale_pin_fails_under_the_gates_own_flags` runs the gate's exact command against a
    stale copy of the pins (exit 1) and a current copy (exit 0).

**BOUNDARY.**
- "47 of 78": the frozen table's 79 rows in file order (their merge order), each append from the
  2nd to the 79th, ids compared as strings. Measured at main `173b4818` (45 of 76 at `2b9b766c`).
- "27 pages": every `data/dossiers/*/dossier.json` at `2b9b766c`.
- "55 files": `frontend/dossiers/` after `python frontend/build.py`, 27 JSON, 27 md and
  `index.json`.
- Measured 2026-11-11.

**WHAT IT COSTS / WHAT IS ACCEPTED.**
- A joined stamp (`A+B`) can appear on a page built between two parallel merges and the next
  vintage. It is declared and names each part. A reader meets a longer stamp, never a wrong one.
- The drift guard cannot tell a pin written today from one written last month. So a re-pin that
  names an OLD vintage for a new hash passes, and is read in the PR's diff. The old rule had the
  same limit for refactors.
- A pin file's `why` is a single declared vintage or `refactor`. A joined stamp is refused there.
- Falsifier for the design: two PRs that each add one vintage and move different modules, cut
  from one main, conflicting textually.
