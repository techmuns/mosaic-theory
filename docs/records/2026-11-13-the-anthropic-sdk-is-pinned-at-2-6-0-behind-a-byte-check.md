# The `anthropic` SDK is pinned at 2.6.0 with a hashed lock that CI installs from, after a $0 check found all 452 request bodies byte-identical to 0.112.0's; every run record now states its SDK (operator: "Check, then pin newest (Recommended)", and the coordinator's default 7)

**WHAT.**
- **The authority.**
  - The operator, 2026-11-13, verbatim: *"Check, then pin newest (Recommended)"*. The option it
    answered read: "A $0 check that the HTTP request bodies for all 27 pages are byte-identical on
    0.112.0 and 2.6.0. If they are, pin 2.6.0 with a lockfile; if not, stop and report. Every run
    record also starts storing its SDK version."
  - This also builds default 7 of `docs/records/2026-11-12-operator-delegation-and-defaults.md`
    ("the `anthropic` SDK gets an exact pin and a lockfile"), a coordinator default. Its first
    build stopped at VERIFY-AT-BUILD: B's claim that 0.112.0 was "the version every paid run used"
    is false (WHY).
- **The pin.** `pyproject.toml` asks for `anthropic==2.6.0`, where it asked for `anthropic>=0.112`.
  The upgrade rule is written beside it.
- **The lock.** `requirements.lock` pins all 52 packages of `.[dev]` with their sha256 hashes,
  `pyarrow==26.0.1` included.
  - It was generated by `uv pip compile pyproject.toml --extra dev --universal --python-version
    3.11 --generate-hashes -o requirements.lock`, using uv 0.13.8 in a throwaway venv. The file's
    header carries that command.
  - Every version is the one the shared venv on the operator's Mac already ran (`pip freeze`, 47
    packages). The exceptions are the SDK and the dependencies only 2.6.0 brings. Those
    dependencies are at the versions the theme desk's 2026-11-09 paid Actions run installed
    (`httpx2` and `httpcore2` 2.16.0). `distro` drops out: only 0.112.0 needed it.
- **CI installs from the lock.** Five workflows install
  `pip install --require-hashes -r requirements.lock`, then the package with
  `pip install --no-deps -e .`:
  - `gate`, `monthly-score`, `theme-intelligence-weekly` and `weekly-screen`, which ran
    `pip install -e ".[dev]"`;
  - `validate-keys`, which ran `pip install --upgrade pip anthropic httpx` and still never
    installs `vinci`.
- **Run records state their SDK** (`graph.llm.sdk_version`). The field is `sdk_version`, and it is
  `null` where no SDK carried a call:
  - the assembly run record (`vinci/dossier/run_metrics.py`, schema 2 → 3), `null` on a build
    that made no call (no LLM client, or refused before its first);
  - each evals draw row, in the approval's ledger and the raw draws file (`evals/replay.py`
    `GuardedSdk`), which the judge's runs share;
  - each theme-desk paid-call ledger row (`theme_intelligence/pipeline.py` `_llm_call`), `null` on
    a cached answer.
- **The check is committed** (`scripts/sdk_byte_check/`, procedure in `capture.py`). It is held
  by `tests/test_sdk_byte_check.py`, and the lock's agreement with `pyproject` and the workflows
  by `tests/test_dependency_lock.py`.
- **Five comments** said the `validate-keys` workflow "installs only anthropic and httpx". They
  are corrected to "never installs `vinci`", which is what their tests rely on.

- **Local builds.** Two records say they ran 0.112.0
  (`docs/records/2026-10-05-pending-after-the-forward-multiples.md`, and
  `docs/records/2026-11-06-synthesis-eval-harness-design.md`, which found CI on 2.6.0 and local on
  0.112.0). None of the 44 committed assembly run records says which, because none had the field.
- **Why uv.** The lock must install on CI (Linux, Python 3.12) and on the operator's Mac (macOS,
  Python 3.14).
  - `uv pip compile --universal` resolves once for every platform and Python from 3.11, with each
    package's hashes, and writes a file plain pip installs. CI needs no uv. Only regenerating the
    lock does.
  - pip-tools resolves for the one platform it runs on.
  - pip's own `pip lock` writes `pylock.toml`, which pip cannot yet install from.

**HOW VERIFIED.** Every step was at $0. Captures, inputs and venvs sit in a scratchpad outside the
repo, because the request bodies carry licensed transcript text.

- **The venvs.** Two throwaway venvs on Python 3.14.3, never the shared one:
  - A installs the shared venv's `pip freeze`;
  - B installs `requirements.lock` with `pip --require-hashes`.

  Their `pip freeze` differs in six lines only: `anthropic` 0.112.0 → 2.6.0, `distro` removed, and
  `httpcore2` 2.16.0, `httpx2` 2.16.0, `opentelemetry-api` 1.45.2 and `truststore` 0.10.5 added.
- **The inputs.** Every committed page's synthesis inputs (the page as built, material marked, and
  its transcript text) came from the impact check's own $0 builds: `python -m vinci.impact run
  --no-shortcut` at main `f2e31cea`, with the shared store (all 27 pages priced to the 2026-11-09
  close), CIQ and cache at the primary checkout, and vendor pulls refused. The capture module
  saved the inputs (`build_inputs.py`).
  - **26 of 27 pages built.** PARR's build refuses: `CiqMislabelledError`, its quarterly
    Financials export stating Period Type 'annual', a known re-export item. PARR went through
    instead as its committed page, with the 53 of its 56 transcript driver rows whose words are
    off the page removed, and no transcript, because the bundle refuses the same export
    (`committed_input.py`).
  - The build ran on two sides at one code. The two sides' inputs differ only in timestamps:
    `assembled_at`, `anchor.computed_at`, and fetch times inside caveats.
- **The capture.** Each venv sent every input through production code to its own real SDK,
  wired to a MockTransport that keeps the exact bytes and answers "stopped at max_tokens"
  (`capture.py`). Each page path has 26 distinct bodies of 102,628 to 731,194 bytes. All 23 pages
  with a transcript carry its text in the body.

**BOUNDARY.**

  judge pages, 2 theme requests and 1 ping.
- **"27 pages"** is `data/dossiers/*/dossier.json` at main `f2e31cea`. "26 built" means
  `inputs/head` held 26 page inputs.
- **The Actions table** is all four runs `gh run list` returns for that workflow, read 2026-11-12.
- **What was not compared:**
  - the environments those Actions runs installed, which were each day's newest packages. The

    versions of the other packages;
  - the graph track's extraction and judge, covenant and driver extraction, and rank's cause
    call. They send through the same `extract` call as the synthesis's one-draw request, with
    their own words.

**WHAT IT COSTS / WHAT IS ACCEPTED.**
- **The server sees new headers, and a $0 check cannot measure what they change.** The API
  version moves from `2023-06-01` to `2026-10-21`, and the key moves to a Bearer header. The
  theme desk's three paid runs on 1.17.0, 2.3.0 and 2.6.0 completed. The dossier synthesis has
  never been paid on 2.x.
  - **Falsifier:** the next paid builds' run records now carry `sdk_version`. Set the first
    builds on 2.6.0 against those on 0.112.0: same failed-call and truncation rates, same draw
    agreement on unchanged inputs.
- **The operator's Mac and B's machine still run 0.112.0** until each re-syncs its venv from the
  lock. Agents are told not to reinstall packages in the shared venv. Until then local builds send
  0.112.0's headers, with bodies identical. STATE §5.0 row 62 holds it.
- **Two installs stay unpinned:** pip itself (`--upgrade pip`), and the build backend that `pip
  install -e .` fetches (hatchling). Neither reaches a request.
